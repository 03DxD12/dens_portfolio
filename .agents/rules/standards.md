# 🛡️ Code Quality, Execution Loops & Structural Rules

Every code generation, modification, and review task in this codebase must strictly observe these 9 integrated tools:

| # | Tool / Methodology | Core Mandate |
|---|-------------------|--------------|
| 1 | **SkillSpector** | Conduct repository scanning, contract auditing, and file inspection prior to making changes. Eliminate dead code and stale assets. |
| 2 | **Reticle** | Maintain laser focus on targeted code blocks. Match existing 2-space indentation, naming conventions, and double-quoted styling. Zero collateral impact. |
| 3 | **Chisle** | Execute precise, localized diffs over whole-file overwrites. Preserve comment integrity, whitespace, and bracket symmetry. |
| 4 | **UI Skills** | Enforce dark luxury aesthetic (`#040914`, `#00f5c4`, `#38bdf8`), glassmorphism, responsive viewports, WCAG AA contrast, and zero-placeholder policy. |
| 5 | **Anti-Slop** | Ban filler code, restating comments, hallucinated helpers, empty TODOs, and speculative boilerplate. Produce high-signal, production-ready code. |
| 6 | **GSD Loop** | Break complex initiatives into sequential sub-tasks. Execute step-by-step to prevent context saturation and hallucinations. |
| 7 | **Ralph Loop** | Test, inspect, and refine code through iterative self-correction cycles with fresh context until all acceptance criteria are met. |
| 8 | **Ponytail** | Anti-overengineering. Rely on native Vanilla ES6+, CSS custom properties, and KISS/YAGNI principles. Minimize token and runtime overhead. |
| 9 | **CodeRabbit** | Automated reviewer pass before finalization. Audit for XSS, client credential exposure, memory leaks, event listener cleanup, and accessibility. |
